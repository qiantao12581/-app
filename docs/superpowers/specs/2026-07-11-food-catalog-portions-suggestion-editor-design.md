# 食物库、份量单位与可编辑餐次建议设计

## 1. 目标

本次升级在现有 iOS 16 营养记录 App 上完成四项改进：

1. 将经过审核的内置食物库扩充到 150 种，区分同类食品、品牌与规格。
2. 支持克、毫升、个、盒、杯、碗和大小份等份量单位，并自动换算营养。
3. 为全部食物提供统一的类别缩略图和细分标签。
4. 修复添加表单底部遮挡，并允许编辑、替换、增删和批量保存餐次建议。

最低部署版本继续保持 iOS 16.0，使用 Swift、SwiftUI 和 Core Data，不引入第三方库或在线运行依赖。

## 2. 数据范围与来源

首批食物库严格保持 150 条，目标分配为：

- 约 100 种高频通用食物，包括主食、肉蛋、水产、奶类、豆制品、蔬菜、水果和常见零食。
- 约 20 种中国大陆常见品牌牛奶、酸奶和饮料，包括特仑苏纯牛奶以及全脂、低脂和脱脂等不同类型与规格。
- 最多 15 种麦当劳中国单品。
- 最多 15 种肯德基中国单品。

如果麦当劳或肯德基没有足够的中国大陆官方完整营养资料，不使用第三方数值补足名额；空出的名额转给有可靠来源的通用食物或品牌预包装食品。

来源优先级如下：

1. 中国疾病预防控制中心营养与健康所食物营养成分查询平台和《中国食物成分表》。
2. 中国大陆品牌官网、官方产品页、官方菜单或官方发布的营养资料。
3. 清晰可核验的中国大陆包装营养成分表。

不采用网友上传的热量表、其他国家同名产品数据或仅凭名称推算的数值。官方未公布的字段显示“暂无官方数据”，不生成 AI 估算值。缺少任一三大营养素的食物不参与自动配餐，但仍可按已有官方值用于手动记录。

## 3. 食物数据模型

### 3.1 FoodReference 扩展

每条内置食品包含：

- 原有名称、别名、类别和适用餐次。
- `nutrition`：允许字段缺失的 `PartialNutritionValues`，分别保存官方热量、碳水、蛋白质和脂肪；已有值保持原始精度。
- `brandName`：品牌名，可为空。
- `tags`：例如品牌、全脂、脱脂、麦当劳、肯德基。
- `iconKey` 和 `colorKey`：类别缩略图与颜色。
- `nutritionBasisAmount`：官方标注的基准数量，通常为 100 或 1。
- `nutritionBasisUnit`：克、毫升或整份。
- `portions`：可选份量定义数组。
- `sourceType`：中国食物成分表、品牌官网、包装标签或官方菜单。
- `sourceName`、`sourceURL`、`verifiedAt`。
- `dataCompleteness`：完整或缺少官方字段。

JSON 解码继续兼容现有数据。迁移期间为旧条目补齐明确的默认基准和来源元数据，最终校验要求 150 条数据的结构和来源元数据完整；官方未公布的营养字段允许为空，但必须与数据完整度标记一致。

### 3.2 FoodPortion

每个份量定义包含：

- `id`：稳定标识。
- `name`：个、盒、杯、碗、小份、中份或大份。
- `baseAmount`：对应的克数、毫升数或官方整份倍数。
- `baseUnit`：克、毫升或份。
- `allowsDecimalQuantity`：是否允许 0.5、1.5 等小数份量。
- `isDefault`：是否为默认输入单位。

示例：

- 鸡蛋：1 个等于 50 克可食部，允许输入 0.5、1、2、3 个，也可切换为克。
- 特仑苏纯牛奶：1 盒等于对应包装标注的毫升数，同时支持毫升。
- 汉堡和蛋挞：按个计算。
- 薯条和饮料：小份、中份和大份分别保存官方整份营养，不能用简单比例假定不同规格完全线性。
- 米饭：支持克和碗；碗为标准估算份量，用户可以调整换算后的实际量。

### 3.3 FoodRecord 迁移

历史记录继续保存实际摄入的热量和三大营养素，数据库更新不会改写历史值。新增可选字段：

- 输入数量。
- 显示单位。
- 换算后的基准数量和基准单位。
- 内置食物 ID 或自定义食物 ID。
- 四项营养值各自的“是否已知”标志。

现有 `weightGrams` 保留用于兼容旧记录；旧记录显示为克，不进行重新换算。迁移后的旧记录四项营养值默认均为已知。新记录遇到官方缺失字段时以 0 作为数据库占位值，同时把对应“是否已知”标志设为 false，界面和统计不得把占位值当作真实的零。

### 3.4 用户自定义食品

新增 Core Data `CustomFood` 实体，允许用户保存品牌、名称、营养基准、份量定义、图标类别和包装规格。自定义食品明确标记为“用户数据”，不会伪装成官方审核食品。

## 4. 缩略图设计

采用已确认的“类别图标 + 细分标签”方案：

- 同类食物共用一个代码内置矢量图标和颜色，例如奶类、鸡蛋、汉堡、薯条、水果。
- 名称下显示品牌、脂肪类型、规格或份量标签。
- 不复制品牌 Logo、产品包装或受版权保护的商品图。
- 食物搜索、今日记录、历史记录、建议卡片和替换选择器使用同一组件。
- 缩略图组件提供 VoiceOver 文本，不依赖颜色表达全部信息。

## 5. 份量输入与营养计算

食物选择后显示数量和单位选择器。计算流程为：

1. 根据份量定义把数量转换为官方营养基准的倍数。
2. 对热量、碳水、蛋白质和脂肪分别乘以倍数。
3. 实时显示换算后的克数、毫升数或官方份数。
4. 用户可以切换单位或修改实际基准数量。
5. 界面统一显示一位小数，内部保留 `Double` 精度。

对于官方整份数据，直接按份量计算，不先转换为虚构的每 100 克数据。对于缺少官方字段的食物，该字段显示“暂无官方数据”，保存时保留缺失状态。今日和历史汇总在存在缺失字段时显示“部分记录缺少官方数据”，已知合计值标记为“至少”，避免把不完整合计误认为完整摄入量。

## 6. 添加页面与 Tab Bar 修复

- 使用 `UITabBarAppearance` 为系统 Tab Bar 设置不透明背景、顶部分隔线和轻微阴影，形成明确边框。
- 食物、运动和体重页面统一使用安全区域底部操作栏。
- “保存到今天”从 Form 的最后一个 Section 移到 `.safeAreaInset(edge: .bottom)` 中，始终位于 Tab Bar 上方。
- Form 增加相应底部内容间距，最后一项输入不会被保存栏遮挡。
- 保存栏拥有独立背景和顶部分隔线，键盘显示与隐藏时仍可访问。

## 7. 可编辑餐次建议

建议卡片点击后打开 `MealSuggestionEditorView`，编辑器维护一份本地草稿，不直接修改今日记录。

用户可以：

- 修改每项的数量和单位。
- 在同一类别中替换食物。
- 添加新食物或删除已有食物。
- 查看整餐实时热量和三大营养素。
- 查看吃完后当天各营养素还差多少或会超出多少。
- 点击“一次性保存这餐”，把各项分别保存为同一餐次的独立 `FoodRecord`。

批量保存使用同一个 Core Data context：先验证全部条目，再创建全部记录并执行一次保存。任一条目无效或保存失败时回滚整餐，不留下半套餐次。

替换列表默认限定同类别，用户可以切换为全部类别。数据不完整的食物可手动选择，但明确标记缺失字段，并且不作为自动推荐候选。

## 8. 数据审查工具

增加食物库审查器和测试，构建时检查：

- 食物总数必须等于 150。
- ID、名称和别名冲突。
- 负数、非有限营养值和无效份量。
- 品牌食品是否包含来源、核验日期和规格。
- 来源 URL 格式与来源类型。
- 每种食物是否有默认份量、类别图标和颜色。
- 官方整份、小份、中份和大份数据是否被错误地当作线性克数换算。
- 数据完整度标记与实际缺失字段是否一致。

热量与三大营养素只做异常值提示，不以 4/4/9 公式覆盖官方数值，因为官方标签可能受纤维、糖醇和修约规则影响。

## 9. 错误处理

- 无效数量、负数、小数不允许的份量和缺失营养字段显示中文说明。
- 食物库解码或审查失败时，保留手动输入和自定义食品路径。
- 来源不完整的品牌食品不进入发布版 JSON。
- 建议编辑过程中不写数据库，取消时直接丢弃草稿。
- 批量保存失败时回滚全部新记录并保留编辑内容。
- Core Data 使用轻量迁移，覆盖安装时保留现有记录和目标。

## 10. 测试与验收

采用测试驱动开发，覆盖：

- 鸡蛋按 1 个、2 个、小数个和克数计算。
- 牛奶按毫升与盒计算。
- 汉堡、蛋挞和鸡翅按个数计算。
- 薯条不同官方规格使用独立数据。
- 150 条食物及全部来源元数据审查。
- 缩略图和标签映射完整性。
- 旧 JSON 解码与 Core Data 历史记录迁移。
- 建议修改份量、替换、增删和实时重算。
- 整餐批量保存成功与失败回滚。
- Tab Bar 外观、底部安全操作栏和 iOS 16 编译。

最终 GitHub Actions 必须通过快速核心测试、完整 iOS 模拟器 XCTest、无签名真机 Release 构建和 TrollStore IPA 打包，才交付新版 IPA。

## 11. 已确认决策

- 首批选择 150 种，而不是直接扩充到 300 种。
- 准确性优先于数量；无可靠官方来源时减少相应品牌条目。
- 使用中国大陆产品资料，不混用海外同名产品。
- 缩略图采用类别图标和细分标签。
- 份量采用标准换算并允许用户修改实际量。
- 餐次建议支持替换、增删、改份量、实时计算和批量保存。
- 不生成或展示 AI 估算营养值。
