# iPhone 最终验收清单

本清单将云端自动化证据与真实 iPhone / TrollStore 手工验收分开记录。自动化通过不代表设备检查已经完成；下面所有未勾选项目均仍须在真机执行。

## 自动化验收（最终 CI 后填写）

- [ ] 500 条发布目录通过结构和来源审计：160 / 190 / 80 / 40 / 30，四项营养均完整，ID 和名称均唯一。
- [ ] 目录构建器、Swift 快速核心测试、Xcode build-for-testing 和全部 iOS XCTest 通过。
- [ ] iPhoneOS Release 无签名构建成功，IPA 压缩结构校验成功，IPA 与 `build-info` 构件上传成功。
- [ ] Tab Bar、底部安全区、旧记录快照、官方/非官方推荐资格和紧凑搜索行回归测试通过。

> 自动化同时读取发布版 `foods.json`，确认鸡蛋实际提供 50 克“个”默认份量，20 条毫升基准食品都提供精确的毫升选项；真机仍需检查实际交互、布局和显示效果。

## 真机准备（尚未执行）

使用 iPhone 14 Pro / iOS 16.5.1。先在旧版创建至少一条食物记录、一个自定义食物和每日目标，然后通过 TrollStore **直接覆盖安装**新版 IPA；不要卸载旧版，也不要清除 App 数据。

## 目录、来源与份量（手工）

- [ ] “添加 > 食物”搜索鸡蛋，选择提供“个”份量的鸡蛋条目；输入 2 个后确认折合用量为 100.0 克，热量和三大营养素均按官方每 100 克基准换算，并以一位小数显示本次实际摄入。
- [ ] 搜索 250 ml 盒装奶，选择“盒”并输入 1；确认折合用量为 250.0 毫升。切换到“毫升”后数量变为 250.0，折合用量、每项已知营养和“暂无官方数据”状态均不漂移；再切回“盒”仍保持相同结果。
- [ ] 分别输入空值、0、负数、非数字或非有限数量，确认显示中文错误、不计算营养且不能保存；对不允许小数的“个/份”输入 1.5，确认同样被拒绝且原输入未被清空。
- [ ] 依次搜索“饺子”“肉馅水饺”“素馅水饺”“锅贴”“三全”；确认通用肉馅水饺优先，素馅和煎制类型清楚分开，输入完整品牌名时品牌条目排在首位。
- [ ] 搜索特仑苏、脱脂奶、麦当劳和肯德基；确认每行只显示缩略图、名称、官方/非官方、计量基准、热量和碳水/蛋白质/脂肪，没有冗长来源文字。
- [ ] 打开任一“官方”和“非官方”食品的“数据说明”；确认显示标记、来源、规格、核验日期、可用链接，以及非官方数据的参考提示。
- [ ] 选择含估算字段的特仑苏或肯德基条目；确认四项营养均可计算且明确标记“非官方”，不会显示成官方值。
- [ ] 在搜索、添加、今日和历史中对照同一食物，确认分类缩略图颜色、图标和标签一致，没有品牌 Logo/包装图；开启 VoiceOver，确认缩略图读出食物名称及全部标签且装饰图标不重复朗读。

## 自定义食物（手工）

- [ ] 新建一个含名称、品牌/别名、营养基准和至少一个份量的自定义食物；确认可在“我的食物”中按名称、别名、品牌或标签搜到并用于记录。
- [ ] 编辑该自定义食物后强制退出并重新打开 App，确认修改仍存在；再次编辑确认原始精度和份量保持，最后删除并确认重启后不再出现。
- [ ] 使用测试/迁移夹具预置一条别名 JSON 或份量 JSON 损坏的自定义食物；确认搜索结果和编辑页显示中文读取错误，编辑/保存被停用且原序列化内容未被覆盖，同时仍可从搜索行侧滑或编辑页按钮安全删除。

## 基础记录（手工）

- [ ] 首次打开可看到“今日 / 添加 / 历史”三个标签。
- [ ] 在“今日”设置每日碳水、蛋白质和脂肪目标，三项都显示一位小数。
- [ ] “添加 > 食物”搜索“米饭”，选择“米饭(蒸)(均值)”。
- [ ] 输入 150 克后显示约 176.7 千卡、38.9 克碳水、3.9 克蛋白质和 0.5 克脂肪。
- [ ] 保存后今日总量立即更新；强制退出再打开，记录仍存在。
- [ ] 对今日记录左滑删除，汇总、营养完整性、剩余量、精确热量缺口可用性和餐次建议状态立即重算。
- [ ] 空名称、0 或负数重量、负数营养值均显示中文错误且不清空当前输入。

## 照片和历史（手工）

- [ ] 可从相册选择图片并看到预览。
- [ ] 相机按钮可请求权限并拍照；拒绝权限或相机不可用时不会导致 App 崩溃。
- [ ] 页面明确显示“模拟识别，请手动确认”，进入下一页后可修改名称、重量和营养数据。
- [ ] 照片保存的记录可在今日与历史中看到。
- [ ] 历史页按日期倒序显示每天的热量和三大营养素；点击含完整/不完整记录的不同日期，确认只显示该自然日食物，且每天的“至少”前缀和完整性提示分别按该日记录重算。

## 减脂与建议（手工）

- [ ] 个人资料可保存性别、生日、身高和日常活动类型。
- [ ] 添加体重后，今日页显示估算基础代谢和日常基础消耗。
- [ ] 添加运动后，今日运动消耗和总消耗增加，专项运动没有重复乘活动系数。
- [ ] 热量缺口为正时显示缺口，为负时显示盈余。
- [ ] 可设置每月 3%、4% 或 5% 的减重速度以及目标体重。
- [ ] 自动模式显示预计完成日期和倒计时；手动模式可指定未来日期。
- [ ] 只记录早餐时，今日页给出午餐、晚餐和加餐建议。
- [ ] 再记录午餐后，建议更新为晚餐和加餐。
- [ ] 每张建议卡显示分类缩略图、食物名称、默认份量单位、数量和整餐三大营养素；点击卡片可打开对应餐次的编辑器。
- [ ] 在建议编辑器把一种食物的数量从 1 改为 2，再切换兼容单位；确认折合克数/毫升数、本餐热量与三大营养素、吃完后“还差 / 将超出”均立即更新，内部结果没有因一位小数显示而反向取整。
- [ ] 点击“替换食物”，默认只显示同类别；打开“全部类别”后可跨类别替换。随后添加一种新食物、删除一种原有食物，确认卡片缩略图与整餐合计同步更新。
- [ ] 输入空值、0、负数、非数字以及不允许的小数份量，确认显示中文错误、整餐显示“无法计算”且底部“一次性保存这餐”不可用；修正后恢复可保存。
- [ ] 手动加入缺少官方营养字段的食品，确认缺失项显示“暂无官方数据”、橙色提示可见、未勾选“我已了解缺失项不会按 0 计算”前不能保存，勾选后才可保存。
- [ ] 早餐和午餐已记录时打开晚餐建议，修改后点击“一次性保存这餐”；确认所有项目同时出现在今日记录与历史中，没有半套餐次，晚餐建议消失；若三大营养素仍有正缺口，仅保留加餐建议。
- [ ] 保存整餐后强制退出并重新打开 App，确认每条食物的数量、份量、营养、餐次和缩略图仍正确；从今日逐条删除后建议按剩余记录重新生成。
- [ ] 覆盖安装前保存一条食物记录；新版目录中即使同一 food ID 的营养发生变化，历史记录仍显示保存时的热量和三大营养素，不被目录覆盖重算。
- [ ] 三大营养素全部达到目标后，显示无需额外加餐。

## Tab Bar 与底部操作（手工）

- [ ] 在浅色和深色模式中切换“今日 / 添加 / 历史”，确认 Tab Bar 使用不透明系统背景，内容与 Tab Bar 之间始终有清晰分隔线，滚动到边缘时分隔线不消失。
- [ ] 分别打开添加食物、添加运动和添加体重表单；确认全宽绿色保存控件位于底部安全区内，不被 Tab Bar、Home Indicator 或页面内容遮挡。
- [ ] 打开餐次建议编辑器并显示键盘，确认“一次性保存这餐”始终位于底部安全区、可见且不与键盘或 Home Indicator 重叠。
- [ ] 在上述三个表单中分别聚焦最后一个可编辑字段，显示和隐藏键盘；确认可滚动到所有字段，底部保存控件始终完整可见、可点击且没有与键盘重叠。
